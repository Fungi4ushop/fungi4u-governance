Purpose:
Describe the intended evolution of the operating model.

Status:
Vision

Last Updated:
2026-05-25


Destination

Create a reusable operating system for complex work that:

- reduces dependency on chat history
- reduces manual context transfer
- allows engagements to restart reliably
- supports multiple domains
- preserves authority in documents
- supports publication and history
- remains understandable after long periods of inactivity
- can be operated by another person


Operating Model

Governance
↓

Context
↓

Execution
↓

Publication


Principles

- Discovery precedes design
- Experiment precedes formalisation
- Design precedes automation
- Governance is shared across domains
- Domains emerge when justified
- Approval precedes persistence
- The system must explain itself
- Platforms execute but do not govern


Target State

Level 1
Governed documents

Level 2
Reusable context packs

Level 3
Domain operating model

Level 4
Workspace automation

Level 5
Cross-device operation


Operating Philosophy

The system should require less memory than the work.

The system should guide operation rather than rely on expertise.

Future users should be able to restart work from documents rather than history.

Authority must remain independent from execution platforms.
